# Развёртывание BA Sender — хостинг и нагрузки

## Требования к хостингу

### Память (RAM)

| Конфигурация | Минимум RAM | Рекомендуется |
|--------------|-------------|---------------|
| 1–2 параллельных сессии | 1 GB | 2 GB |
| 3–5 параллельных сессий | 2 GB | 4 GB |
| 5+ сессий, много пользователей | 4 GB | 8 GB |

**Почему:** Один экземпляр Chromium (Playwright) занимает ~400 MB – 1.5 GB. При `max_concurrent=5` одновременно может работать до 5 браузеров.

### CPU

- 0.5–1 vCPU достаточно для 2–4 параллельных сессий
- При высокой нагрузке — 2 vCPU

### Диск

- **Persistent Disk обязателен** — без него данные (аккаунты, сессии, одобрения) сбрасываются при каждом деплое
- Рекомендуется: 1–2 GB

## Render.com — подходит ли?

### Текущая конфигурация (Worker + Docker)

| План | RAM | Подходит? |
|------|-----|-----------|
| Free | 512 MB | ❌ Мало для Chromium |
| Starter | 512 MB | ❌ Мало |
| **Standard** | **2 GB** | ✅ До 2–3 параллельных сессий |
| Pro | 4 GB | ✅ До 5 сессий |

### Рекомендации для Render

1. **Instance Type: Standard (2 GB)** — минимум для стабильной работы
2. **Persistent Disk** — обязательно, иначе данные теряются
3. **Режим: Background Worker** — polling работает без веб-сервера
4. **Регион** — Oregon или ближе к целевой аудитории

### Ограничение нагрузки

При 2 GB RAM лучше уменьшить параллельность. Добавьте переменную:

```
MAX_CONCURRENT=3
```

(если поддерживается — см. config)

## Режимы запуска

### Polling (по умолчанию)

- Подходит для Render **Background Worker**
- Не нужен публичный URL
- Небольшая задержка ответа (~0.5–1 с)

### Webhook (опционально)

Для Web Service (VPS, Railway, Fly.io и т.п.) с публичным HTTPS:

```
WEBHOOK_URL=https://your-domain.com
PORT=10000
```

Бот будет получать обновления через webhook — быстрее и меньше нагрузка на CPU.

## Масштабирование

При росте нагрузки:

1. **Увеличить RAM** до 4–8 GB
2. **Ограничить max_concurrent** — не более 1 сессии на 512 MB RAM
3. **Очередь** — при многих пользователях рассмотреть Redis + воркеры (отдельная доработка)
